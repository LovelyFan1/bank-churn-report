# 前端业务体验改造交付记录

日期：2026-10-23。阶段：第一阶段，梳理信息层级与客户跟进主流程。

后续状态：用户授权后，已将本轮 UI 构建进 Docker 并更新前端容器，可从 `http://localhost:5173/` 体验。详见 [Docker 部署记录](DEPLOYMENT_UI_WORKFLOW_2026-10-23.md)。

本轮目标是让第一次使用的人知道从哪里开始、如何判断、确认什么、到哪里记录结果。主路径统一为：**找客户 → 看原因 → 确认跟进 → 记录结果**。

## 1. 用户能直接感受到的变化

| 页面 | 现在的体验 | 涉及文件 |
| --- | --- | --- |
| 今日工作台 | 先看到优先客户和待办入口；统计、模型依据移到名单下面；汇总失败明确报错并提供重试 | `frontend/src/views/Dashboard.vue` |
| 客户名单 | 姓名可以直接打开详情；搜索和风险筛选优先；其他条件收进“更多筛选”；已生效条件始终显示，可逐个取消 | `frontend/src/views/CustomerManagement.vue` |
| 客户详情 | 看完原因后，可以直接准备跟进；已有工单则进入跟进记录；返回时保留来源名单的筛选 | `frontend/src/views/CustomerDetail.vue` |
| 确认面板 | 工作台、名单、详情共用同一流程，先核对负责人、渠道和理由；只有明确点击确认才创建；失败保留备注 | `frontend/src/components/PrepareOrderDialog.vue` |

| 分层跟进策略 | 矩阵先于收益统计；通过键盘也能进入名单；窄屏表格在局部横滑 | `frontend/src/views/InterventionStrategy.vue` |

## 2. 公共体验与视觉规则

- 导航名称采用业务语言，分析与治理单独分组；桌面顶栏标明仿真业务环境。
- 四步提示在主要业务页面重复出现，当前步骤突出；窄屏采用单行文字，给内容留下空间。
- 延续现有浅色管理台，统一主文字、辅助文字、操作、成功、错误与边界颜色。
- 表单字段有明确标签，客户详情链接、工单展开按钮和矩阵入口支持键盘操作。
- 说明浮层关联按钮与内容，支持 Escape 和外部点击关闭。
- 确认弹窗有独立表面、可滚动正文和固定操作区；短视口及 CSS 放大压力检查时，确认按钮仍可见。
- 工单表保留合理列宽，窄屏局部横滑，避免中文逐字竖排。
- 侧栏宽度变化会通知现有图表调整尺寸；工作台刷新前释放旧图表。

公共实现涉及 `TaskPath.vue`、`Dialog.vue`、`InfoTip.vue`、`layouts/AppLayout.vue`、`router/index.js`、`style.css`。`EdaAnalysis.vue`、`CustomerClustering.vue`、`ModelComparison.vue` 仅调整部分低对比度文字颜色。

## 3. 权限和业务边界

- 继续使用服务端下发的权限。无建单权限时隐藏创建和批量选择入口；无导出权限时隐藏导出入口。
- 客户详情和准备阶段都读取当前客户数据；已有在途工单、历史流失样本禁止提交。人工更换建议渠道时须填原因。
- 精确工单回执复用现有 `GET /work-orders/{id}`，保留后端原有归属检查、404 与脱敏逻辑。
- 助手既有会话版本、确认令牌、撤回、单条与批量确认协议保留；没有引入自动建单。
- 客户卡和工单卡分别处理，不能因为工单可操作就给同一客户重复准备新单；不可建单文案不再一律归因为已有工单。
- 保留现有批量派单、按编号新建、导出、训练入口、编辑及结果复核功能。本轮没有调用训练接口。

UI 改造与隔离验证阶段未修改后端、数据库结构、业务数据、模型及模型指标；未清理历史文件，未新增 Python 文件；未暂存、提交或推送 Git，未覆盖本地 `frontend/dist`。该阶段未执行部署，后续经用户授权仅更新 Docker 前端容器，发布情况见上述部署记录。
