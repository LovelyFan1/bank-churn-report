# 版本同步与验证记录

## 2026-10-23：智能体第二轮修复（E01–E06）

按[修复交接清单](AGENT_REMEDIATION_HANDOFF_2026-10-23.md)处理五组问题，并同步前后端口径：

- **工具错误契约（E01）**：所有工具失败统一为 `ok=false + error_code + retryable`，不再把 `__error__` 包成成功；写提议失败进入工具留痕并由错误码生成确定性回答；批量区分"可准备 N 位 / 不可准备 M 位"，全失败时不签发空确认、不丢剩余名单。
- **模型异常降级（E02）**：决策模型超时/连接失败不再冒泡成 500，有数据时保留卡片并说明"模型解读暂不可用"，无数据时返回 `basis=upstream_unavailable` 且不产生任何事实或待确认动作；未知编程错误仍向上抛出。
- **可信历史事实（E03）**：会话保存 `probability/balance/expected_value` 的结构化事实（10 个回答 / 200 条 / 15 分钟），核验器真正消费它；客户端注入一律丢弃；历史值不能张冠李戴、改指标或改单位，也不影响名单与建单目标。
- **SQLite 并发（E04）**：不切换 WAL（容器内 SQLite 3.46.1 未证明含 WAL-reset 修复）；改为每连接统一 `busy_timeout=30000`，并在启动日志报告实际版本与 journal 模式。
- **工具权限透传（E05）**：Agent 查询改用当前用户的 Bearer，不再使用会被中间件升格为 admin 的内部令牌；无身份直接拒绝；自调地址限回环、跨源重定向中止。
- **前端（协议）**：新增 `operation_rejected / tool_error / upstream_unavailable` 等口径；请求失败不再一律显示"智能体未启用"。

验证：新镜像内后端 226/226、前端 27/27、生产构建通过；未做真实大模型对话与浏览器端到端。部署与回退见[本轮部署记录](DEPLOYMENT_2026-10-23B.md)，SQLite 结论见[并发口径](SQLITE_CONCURRENCY_2026-10-23.md)。
